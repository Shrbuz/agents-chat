# 调度接入

本实现包含会话启动/阶段检查和 bounded watch。安装技能不等于后台服务
已经运行。每个目标会话先明确角色和 session，处理已有任务，再设置其
平台支持的定时唤醒。不要向未经用户授权的目标聊天自动发消息。

已运行的 agent 可以按 [notifications.md](notifications.md) 通过宿主提供
的工具向已授权目标发送一次交接通知；这和持续轮询/周期调度是两件事。
发送成功不证明目标已运行，是否唤醒或排队以该平台实际返回为准。

## Codex 同一聊天周期检查

用户要求持续处理时，用 Codex 的定时任务/heartbeat 工具配置该角色聊天。
保存的提示应包含：项目绝对路径、角色、固定 session ID、检查 inbox 与
status、按 skill 领取和处理可执行任务、检查自己发出请求的回执、有进展
或需要用户操作时才通知、无变化保持安静，以及停止条件。

示例持久提示（替换 PROJECT、ROLE、SESSION 后使用）：

> 使用 agent-chat，项目 PROJECT，当前角色 ROLE，会话 SESSION。检查收件箱
> 和与本角色相关的未关闭任务；领取并处理权限内可执行的工作，发送结果
> 或明确阻塞原因，核查自己发出的任务回执。tester 使用 ego-browser 和
> 当前部署版本执行生产验收。没有可执行变化时保持安静，只在完成、失败、
> 实质进展或需要用户操作时通知。用户停止监控或约定交付任务全部关闭时
> 停止此周期任务。不要将权限请求当作自动批准。

本机项目任务需要机器和桌面应用持续运行、项目路径可访问。这里没有
硬编码目标聊天 ID 或自动新建角色聊天；应在对应角色聊天中设置唤醒。

## Qoder

AGENTS.md 兼容入口在新会话启动时加载规则。已有会话需显式读取入口或
重新加载上下文。若使用 Qoder CLI 的计划任务/headless runner，按实际
安装版本的文档配置角色入口。IDE 中的普通 Hook 依赖用户输入/工具事件，
不能把 Hook 描述成空闲时的外部唤醒器。

## 文件等待

```text
python CLI --project PROJECT watch --role backend --session backend-UUID --interval 10 --timeout 60
```

返回当前未读消息、可领取任务或与该角色有关的状态变化；超时以 timeout
返回。最多等待 300 秒，不启动模型或执行消息正文。没有外部 runner 时
它不会让已经结束运行的聊天自动恢复。先验证真实的收发与唤醒链路，再
对用户报告“持续运行已开启”。
