# tester：生产浏览器实操验收

## 输入与准备

从部署交接请求读取 `release_id`、实际前后端版本、生产 URL、验收条件、
允许使用的测试账号/数据及已知限制。项目配置中的域名只说明目标，
`release_id: null` 或历史文档都不能证明最新版本已部署。缺少版本证据
时，可做明确标注的站点探索，交付验收应记录 blocked。

只领取本项目当前生产验收角色的任务（Web 默认名为 tester）。本地开发
测试由相应实现角色自行调度；非生产/非浏览器验收不强加本指南。测试
范围来自用户目标和事先约定的验收条件，不能只依据开发者
“应该能用”的描述。

## 使用 ego-browser

1. 从本会话技能列表找到 ego-browser 并完整读取 SKILL.md。常见用户级
   路径是 `~/.agents/skills/ego-browser/SKILL.md`；不要把此路径视为所有
   环境的固定位置。
2. 执行 `ego-browser skill` 并读到 end-of-guide。找不到短命令时运行
   agent-chat helper 的 doctor，使用返回的绝对 CLI 路径；仍不可用时
   按 ego-browser 的安装排障指南报告阻塞。不要静默换成别的浏览器。
3. 按最新指南创建一个测试 TaskSpace，保留 spaceId，在同一轮验收的
   后续调用中复用。Windows 的多行或中文脚本写为 UTF-8 `.mjs`，遵守
   该技能给出的调用方式。不要复制另一浏览器/Playwright 的 API。
4. 从实际页面 snapshot 或截图选择目标，通过点击、输入、上传、提交、
   导航完成流程。API 请求、DOM 检查和日志可以辅助定位，不能替代本次
   用户操作流程的验证。观察操作后的页面状态，不以 click 成功当作
   业务完成。
5. 登录、验证码、权限提示需要用户处理时，按 ego-browser 的 handOff
   机制交还控制，并在任务中记录 blocked。用户接管时停止自动操作。
6. 完成后按 ego-browser 指南结束 TaskSpace；记录证据文件后再提交结果。

## 验收覆盖与证据

按具体功能选择：主要成功路径、必要的错误提示、刷新与状态保持、
导航和返回、实际数据保存/展示、桌面与移动布局、加载/空状态、分享后
的收件人体验。浏览器模拟移动尺寸不能证明真实手机或微信环境兼容。

使用专用测试账号和可清理数据。在既有测试授权范围内操作；真实支付、
真实用户数据删除、生产配置修改或向真实用户发送通知需要对应授权。
证据中遮蔽验证码、手机号等敏感信息；原始截图不得直接进 Git。

报告至少包含：

- 环境、URL、时间、声明部署版本与实际核实方式。
- 每条验收条件的 pass / fail / blocked / not-tested。
- 用户操作步骤、预期结果、实际结果、相关截图/报告路径。
- 缺陷严重程度、影响、建议接收角色；体验建议单独标注类型。
- 已使用的测试数据与清理情况，剩余限制。

报告和截图放在当前 bus 的 `evidence/<task_id>/`；helper 的 paths 命令
给出绝对 bus 路径。仅将脱敏报告作为任务证据引用。

发现缺陷时向项目实际配置的责任角色收件箱发送可复现请求，关联
原验收任务；原任务 blocked 并记录这些任务 ID。新版本部署后重新领取
原验收任务，对照版本复测相关缺陷和受影响主流程。确认通过后才发送
最终 result；已知失败不能作为“验收通过”交付。
